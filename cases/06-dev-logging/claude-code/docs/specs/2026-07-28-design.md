## Universal ingest (operator requirement, 2026-07-28, after first real-log trial)

Field trial verdict: the tool must read **any log the user points it at** —
unknown formats are the norm, not the exception. Requirements (upgrade to
`ingest.py`, shipped as a phase-1 hotfix):

- `--logs` accepts a directory, a `.zip`, or a **single file** of any name.
- Directory walk includes **every regular file** regardless of extension
  (`.out`, extensionless `LOG`, rotated names). Exclusions are explicit and
  visible, never silent: binary files (null-byte sniff in first 8KB),
  nested archives (skipped with a note; `.gz` is read transparently via
  gzip), oversized files (cap with a note). `stats` reports per-file
  format decision + ok/partial/unparsed counts + skipped-files reasons —
  «didn't know the format» must be diagnosable in one command.
- **Generic text parser fallback** (after the existing logback/JSON paths,
  which keep byte-identical behavior on the pack): timestamp bank at line
  start (ISO `T`/space with `.`/`,` millis + optional tz, syslog
  month-name, epoch millis) normalized to ISO; optional `[thread]`; level
  as a standalone token near line start (incl. SEVERE/CRITICAL→ERROR);
  separator variants (` - `, ` — `, `: `). **Multi-line folding:** a line
  with no leading timestamp is a continuation — appended to the previous
  record's body (Java stack traces become one record), never a stream of
  UNKNOWN singletons.
- Verified against the operator's real Flink logs (log4j
  `YYYY-MM-DD HH:mm:ss.SSS [thread] LEVEL logger - msg`) as a named test
  fixture.

## Normalization v2 — LLM-inferred formats (operator-approved 2026-07-29, priority: make current solution work on ANY real logs)

Supersedes pattern-bank thinking. Extraction order per file:

1. **Learned-format cache:** `formats.d/learned/<fingerprint>.json` — fingerprint
   = hash of the format's stable shape (masked skeleton of sample lines).
   Cache hit ⇒ apply stored pattern deterministically, zero LLM.
2. **Heuristic extractors** (no format assumption): timestamp discovered
   ANYWHERE in the line (position becomes part of the learned format and
   drives continuation folding), level token, service (structured keys →
   logger heuristic → filename), **generic ID discovery** (UUIDs/hex/
   `*_id` key=values — no hardcoded key list).
3. **Exit-4 inference handshake** (model proposes, code disposes): unknown
   dialect ⇒ CLI exits 4 printing a JSON request (sample lines +
   instructions). The DRIVING AGENT (qwen/Claude — it IS an LLM) derives a
   format descriptor (named-group regex / field map incl. timestamp
   position+format) and calls `logalyzer register-format <file>`. The tool
   VALIDATES against the sample (hit-rate thresholds, e.g. ≥90% timestamps),
   rejects bad patterns, stores accepted ones in the learned cache
   automatically. LLM cost: once per dialect, never per line. Direct-API
   mode = possible later config, not now.
4. **Container detection goes content-based** (JSON-lines/logfmt/CSV/pretty
   JSON/free text scored on samples; filename only a hint) — fixes
   filename-triggered kafka/k8s/trace sniffing.

**Time-frame correlation (IDs optional):** `investigate` accepts
`--correlation-id` OR `--since/--until` OR `--around <ts> --window <dur>`;
without an id the timeline is the time window (optional service filter);
the report states its correlation basis. Downstream unchanged.

`stats` reports per file: dialect used (heuristic|learned:<fp>|inferred),
extractor hit rates. SKILL.md documents the exit-4 protocol next to exit-3.

## Two lanes

**Sherlock (on-demand, TC-01):** complaint/correlation_id → ingest+correlate →
evidence bundle → agent reasons per SKILL.md (trace failing span → culprit logs
±60s → `search_repo` on stack identifiers → SDD invariant И-1 citation) → RCA
JSON + fix diff → `gates.py` validates → report (redacted by default, RU). Handles the
`handleReservationTimeout` trap by construction: gate rejects citations of
nonexistent methods. p95 ≤60s: deterministic part is sub-second; the LLM call
is the only variable and gets one retry budget.

**AIOps (stream, TC-02/TC-05):** replay `synthetic_stream.jsonl` (or live
tail) through `detect.py`. Early-warning ≤30s by code-only triggers; TC-05
false-positive guard = the same rules/thresholds must stay silent on the
healthy control traffic (generator emits a clean stream variant for this).
LLM strictly out of the hot path.

**Self-learning (TC-03):** after Sherlock solves incident 1, `save_case`
persists it as `proposed`; a human (operator/CLI/`submit_feedback`) confirms
it — the scored feedback loop. Incident 2 (notification) hits `similar_cases`
(confirmed-only) → fuzzy match on the "timeout → dropped work → no retry"
pattern → agent receives the solved case as context → measured time-to-RCA
≥30% faster. Honest because R-NOTIF-001 carries `status: quarantined` and the
warm report explicitly marks which case was reused. Warm-run findings still
come from the generic rule families + template miner (not notification-specific
rules), so the speedup is attributable to knowledge reuse alone.

## Personas and launch context (operator requirement, 2026-07-28)

Two user personas, one tool:

- **Developer (has code access):** full RCA — the report points at file +
  method (+ line) in the real repo, code recommendations included; every code
  citation validated against the repo tree (gate).
- **DevOps (no code access):** logs-only mode — RCA stops at
  service/component level with evidence and operational recommendations
  (restart/scale/config/escalate); `code_recommendations` explicitly states
  code access is required for file-level RCA. No degraded-quality claims:
  the report says what mode it ran in and why.

**Target agent runtime (operator, 2026-07-28):** on event day the skill is
driven by the corporate **qwen-coder-like CLI agent** — all interactions via
CLI. Consequences: no MCP dependency in phase 1 (CLI commands are the whole
contract); SKILL.md is short, imperative RU markdown a qwen-class model
follows reliably; machine-readable handshakes (exit codes, JSON to stdout)
instead of any harness-specific feature. Claude Code drives the same CLI
during development — that dual-run IS the agent-agnostic proof for М4.

**Auto-invocation by intent (operator, 2026-07-28):** the skill must be
picked up by the qwen agent from USER INTENT, not only by name. SKILL.md's
frontmatter `description` enumerates the trigger situations in RU (заказ/
платёж упал, разбор инцидента, «почему ошибка», анализ логов/стенда, жалоба
QA, пользователь прислал correlation_id или фрагмент лога) and the body
opens with a «Когда применять» section listing the same intents — so a
qwen-class matcher fires on the situation description, never requiring the
skill's name.

**Launch-context rule (SKILL.md + CLI):** on start the tool detects whether
source code is reachable (markers: `.git`, `pom.xml`, `src/`, `services/` in
cwd/given paths). If the agent is launched OUTSIDE a code dir: it must ASK a
clarification question — pointing at likely code dirs it found
(`suggest-repos` scans cwd, parents, siblings) or asking the user to provide
paths; "no code" is an accepted answer that selects DevOps mode. Mode is
never silently guessed.

## Live stand connector — Flink over SSH (operator requirement, 2026-07-28; implement later, separate worktree)

Real AIOps input exists: the operator's dev stand runs Apache Flink, logs at
`/opt/flink/current/log/` — active log4j-format `.log` files
(`flink-<svc>-client-*`, `-standalonesession-N-*`, `-taskexecutor-N-*`),
daily-rotated `.zip` siblings, empty `.out`, RocksDB `*_db_LOG` files.
Format `YYYY-MM-DD HH:mm:ss.SSS [thread] LEVEL logger - msg` — already
parsed by our plaintext reader; multi-line stack traces become `partial`
records (existing behavior).

**`logalyzer watch` (new CLI mode):**

- **Transport:** shells out to the system `ssh` binary (subprocess —
  universal, stdlib-only). Auth: identity file preferred; **password
  supported via config** using `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force`
  (no sshpass dependency). Config file chmod-600-checked; password never
  logged, never enters reports. **Reconnect per poll cycle** — the stand
  force-closes idle sessions (observed `auto-logout`), so no persistent
  connection is ever held.
- **Config (INI, configparser — py3.9 floor rules out tomllib):**
  `[stand] host, port, user, identity_file | password | password_env,
  log_dir, file_glob (default flink-*-*.log)`; `[watch] poll_seconds
  (default 30)`. Operator sets username/server/password here — nothing else
  to install or configure.
- **Incremental pull:** local per-file byte-offset cursors (state under
  `artifacts/watch/`); each poll: one `stat`-sizes exec, then
  `tail -c +<offset+1>` per grown file; size < cursor ⇒ rotation → reset
  to 0; new files matching the glob auto-tracked; rotated `.zip`/`.out`/
  `*_db_LOG` ignored in live mode.
- **Scheduling — universal by construction:** an in-process foreground
  loop. While the CLI runs, it polls; Ctrl-C stops it. No cron/systemd/
  launchd/OS-specific anything — the machine only needs Python and `ssh`.
  A `--once` flag runs exactly one poll tick and exits (scriptable from any
  external scheduler if someone wants one; also the test seam).
- **Detection on each tick:** new records → mask → rules engine (+ detect.py
  triggers when Phase 2 lands; until then rules + an ERROR-burst heuristic)
  → «something strange» prints as an RU alert line with evidence refs to
  stdout and appends to the run log.
- **Liveness test (required by operator — "the CLI is really firing"):**
  (a) a `--source local:<dir>` variant runs the same cursor/poll/detect
  machinery against a local directory with no SSH; the test starts a watch,
  appends an ERROR burst to the watched file, and asserts an alert is
  emitted on the next tick; (b) ssh-argv builder unit-tested without any
  network; (c) `--once` makes both deterministic.
- **Open question:** verify the `SSH_ASKPASS_REQUIRE=force` password path
  against the real stand's OpenSSH version (fallback: key auth, or
  `sshpass` if present).

## Generator (`streamgen/`) — TC-02 synthetic stream

Deterministic, single-seed, reproducible; a first-class robust subsystem
(operator directive). Design from the `research-synthetic-log-generation`
workflow (web-sourced, every rate carries a literature citation in config):

**Architecture — two stages, config-first, no DSL.** Stage 1 simulates a
world (4 services + gateway + Kafka + k8s control plane as small state
objects on a 1s tick; declarative phase table for the scenario) and emits a
CLEAN ground-truth event stream, top-down: user sessions → funnel → span
trees, so any trace_id reconstructs a coherent causal story. Stage 2 pushes
it through ordered composable **corruptor passes**, then per-service
**dialect renderers** (each service has a fixed format identity: JSON vs
logback plaintext, different timestamp formats, different trace-id key,
multi-line stack traces as separate records), and a heapq merge with
deterministic tiebreaks emits `synthetic_stream.jsonl` + `ground_truth.jsonl`
+ manifest. A healthy control stream variant serves TC-05.

**Statistical realism (the audit-enforced targets):** NHPP arrivals
modulated by a 3-state MMPP burst chain + 5% Pareto heavy-tail gaps (never
uniform); diurnal slope so rate drifts ~15-20% across the 30-min window;
~110 templates with Zipf weights (top-10 = 70-85% of lines, ≥25 templates
fire <5 times); per-service lognormal latencies with 3% ×10 stragglers;
incident as a **metastable cascade with a real feedback loop** — memory-leak
trigger, ≥8 min of precursor WARNs (the honest ≤30s-early-warning
substrate), retry-storm amplification as live state, logistic error curve,
degradation persisting past the trigger, recovery only via a logged
intervention (deploy + thundering-herd echo).

**Dirty data:** per-service systematic quirks (consistency-per-codebase, not
random noise) + a knob-per-defect catalog with plausible default rates:
broken templates (`Processing order null`, slf4j `{}` leaks), duplicate
log-and-rethrow pairs, swallowed exceptions, Kafka re-delivery bursts,
per-host clock skew + collector reorder (1-5% out-of-order), missing fields,
one PII-leaking DEBUG template, mid-incident schema drift.

**Discipline:** named per-concern PRNG streams
(`sha256(seed:name)`-seeded) so features never perturb each other's draws;
no `time.time()`/`uuid4()`/builtin-`hash()`; `--self-test` = byte-identical
double run; `--audit` re-reads the *emitted file* and FAILS generation if
output is "too clean" (inter-arrival CV, template histogram shape,
out-of-order share, dialect count, level mix, precursor lead-time) — we
grade ourselves before the organizers' LLM-judge does. ~2,400 lines,
10 modules under `streamgen/` (config/clock/templates/traffic/incident/
noise/corruptors/render/audit/generate).

## Safety posture (jury differentiator)

Inert-data frame (tssa corrections-triage, verbatim): log content is data,
never instructions — a log line that looks like a command is itself a finding.
Model-proposes-code-disposes at every LLM boundary (gates, deterministic
classification/detection). `run_on_stand` gated + audited. PII masked before
any LLM call; reversible only locally.

## Observability — data-driven improvement loop (2026-07-28)

Operator directive: the system must be observable so the team improves it
FROM DATA. Design from the observability-eval workflow (audit + web practices
+ tssa patterns): **one ledger, one analyzer, instrument what already
exists** — ~420 stdlib lines, hooks only in already-designed modules.

- **Two sinks via one seam** (a ~30-line RunLog writer in observability.py):
  per-run event stream `artifacts/runs/<run_id>/events.jsonl` (records with
  `kind`: alert | gate_reject | mcp_call | retrieval | llm_call |
  parse_error, correlation-id-stamped) + repo-level append-only
  **`docs/runs.jsonl`** — one line per benchmark invocation keyed by
  {run_id, git_sha, rubric_sha, rules_sha, seed, mode: llm on/off × cold/warm}
  carrying: per-defect hit/miss vector with **miss-reason taxonomy**
  (not_ingested → no_template → no_rule_fired → rule_fired_wrong_key →
  gate_rejected → below_threshold), per-rule attribution, stage-timing
  vector, LLM token/latency/reject accounting, detect headroom/flap counters,
  end-of-run Prometheus-registry dump (makes A4.1 counters durable). JSONL
  over sqlite: single writer, git-committable (the ledger IS the Ж1/Ж3
  evidence trail), diff-exact under seeded determinism.
- **`analyze.py`** (~150 lines, zero LLM) answers the H6/H12/H18 decisions:
  `--misses` ranked missed-defect queue by reason [H6: which rules next];
  `--rules` per-rule precision incl. **control-stream FP oracle** (every
  match on the TC-05 healthy stream is a false positive by construction;
  dead-rule and >5%-FP flags; shadow-promotion list); `--diff` run-over-run
  flip lists (regressed/fixed per defect); `--llm` baseline-vs-enriched value
  delta [H18: LLM on/off]; `--stages` time budget vs the 60s p95;
  `--headroom` threshold margin/flap report [H12]. Dual-emitted: ranked human
  digest + stable-path JSON (tssa digest pattern).
- **Shadow rule status:** rules dialect `status` becomes
  `active | shadow | quarantined` — shadow rules evaluate and count but never
  emit; new rules land shadow → one replay → `analyze --rules` → promote.
  Upgrades the R-NOTIF-001 quarantine into a principled 3-state lifecycle.
- **Decoupled signal vs action in detect.py** (tssa lesson): z-score recorded
  every window regardless of firing; sustained-fire action threshold
  separate; one guard test pins the decoupling.
- **LLM value A/B:** benchmark runs both modes on the same seed when the
  enrichment flag is available; gates.py counts rejections by reason
  (nonexistent-method / uncited-log-line / bad-rule-id / bad-severity).
- **MCP audit record pinned:** {ts, correlation_id, tool, arg_digest,
  latency_ms, result_bytes, truncated, error}; `search_repo` logs hit/miss;
  `similar_cases` logs top-k scores incl. below-threshold near-misses (the
  data that tunes the TF-IDF threshold).
- **CI regression gate:** committed baseline ledger line; verify.sh lane runs
  `analyze --diff BASELINE CURRENT` and FAILS if any previously-hit defect
  regressed — deterministic, LLM-free inner loop (change rule → run → diff).
- **Jury surface:** `/metrics` (A4.1) exposes the pinned low-cardinality set,
  adopting OTel GenAI semconv NAMES only (`gen_ai_client_token_usage_total`,
  `gen_ai_client_operation_duration_seconds`); three pitch artifacts generate
  FROM the ledger: recall-over-commits chart, per-rule precision table with a
  shadow→active promotion story, LLM-value delta table.
- **Schedule fix (critical):** the ledger + per-defect scorecard +
  `analyze --misses/--diff` move INTO Increment 1 (the e2e demo writes its
  first ledger line at hour 1) — H6 rule-tuning and H12 threshold decisions
  must not run blind. `/metrics` + SSE + api stay in Increment 3.
- **Non-goals:** OTel SDK/OTLP, separate spans file, sqlite run ledger,
  dashboards beyond /metrics + digest, per-template metric labels
  (cardinality), any observability costing more to build than the insight
  it yields.
