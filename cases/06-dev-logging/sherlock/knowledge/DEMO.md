# Демо цикла самообучения — 90 секунд

Показываем ровно одно: **инцидент №1 научил систему, инцидент №2 решается быстрее,
и между ними стоит человек.**

Всё, кроме необязательного шага 5, работает **офлайн и мгновенно** — на сцене нет
ни одного вызова LLM, который может подвиснуть. Живой прогон вынесен в опцию.

## Подготовка (до выхода на сцену)

```bash
cd cases/06-dev-logging/sherlock/knowledge
export L=~/hack/logalyzer-real-world-testset/real-logs

# «инцидент №1» — база знаний ещё пуста

```

Открыть два окна терминала: слева `/tmp/demo/kb` (пустая база), справа рабочая
`knowledge/` (база с карточками). Шрифт крупный, история очищена.

## 0:40–0:55 — И отказ тоже знание

```bash
python3 patterns.py reject possible-break-in-attempt-means-breach \
  --reason "PTR/A-несовпадение, а не взлом: 85 строк при одном успешном входе" \
  --by operator \
  --signature "POSSIBLE BREAK-IN ATTEMPT" \
  --signature "reverse mapping checking getaddrinfo"
python3 patterns.py rejected
```

> «Агент предлагал и это: строка `POSSIBLE BREAK-IN ATTEMPT` выглядит как взлом.
> Инженер отклонил — это несовпадение DNS-записей, в нашем же корпусе таких строк
> 85 при одном успешном входе. Отказ записан **вместе с причиной** и хранит
> отпечаток подписи: та же идея под другим именем повторно не пройдёт. Ошибка,
> которую цикл выучил бы сам, теперь не выучится никогда.»

## 0:55–1:20 — Инцидент №2: другой корпус, другой формат

```bash
cd -                                  # рабочая knowledge/ с карточкой
python3 patterns.py match $L/Linux
```

```
=== ssh-bruteforce-storm — Массовый перебор паролей SSH  (490 совпадений)
    порог подтверждения: ≥20 неудач и ≥3 источника за ≤1 ч
    подпись 'authentication failure;.*rhost=' — 490 совпадений
      Linux_2k.log:1  Jun 14 15:16:01 combo sshd(pam_unix)[19939]: authentication failure; … rhost=218.188.2.4
```

> «Карточку выучили на логе OpenSSH, где строки выглядят как
> `sshd[24503]: Failed password for root`. Здесь — другой хост, другой год,
> другое написание: `sshd(pam_unix)[19939]: authentication failure`. Совпало.
> Расследование начинается не с нуля, а с готовой гипотезы и с указания, куда
> смотреть в первую очередь — искать успешный вход в окне шторма.»

Показать, что карточка ведёт к находке, которую иначе легко пропустить:

```bash
grep -n "session opened for user test" $L/Linux/Linux_2k.log | head -3
```

> «Вот оно. На фоне 490 отказов у пользователя `test` (uid=509) **открываются
> сессии**. Компрометация это или легитимный CI — по логу не видно, и честный
> ответ так и звучит. Но это то, что обязан заметить дежурный, — а холодный
> прогон на этом же корпусе не заметил вовсе. Агент попал сюда потому, что
> карточка велела проверить.»

## Если что-то пошло не так

| симптом | что делать |
|---|---|
| `patterns.py` не запускается | это не поломка демо: показать `patterns/ssh-bruteforce-storm.md` и `REJECTED.md` в редакторе — весь цикл виден глазами, скрипт лишь удобство |
| `match` ничего не нашёл | проверить `$L` (`echo $L`); карточки лежат в текущем каталоге `patterns/` |
| нет сети | ничего не меняется: шаги 1–4 полностью офлайн |
