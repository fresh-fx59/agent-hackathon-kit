# База знаний Sherlock — цикл самообучения с человеком в контуре

Это память навыка. Она устроена так, чтобы её можно было прочитать глазами,
проверить в ревью и передать команде обычным `git commit`.

**Никакой инфраструктуры.** Ни сервиса, ни базы, ни планировщика, ни настройки.
Плоские файлы внутри каталога навыка — они переносятся вместе с ним, поэтому
установка остаётся ровно тем, чем была: «скопировать папку навыка» (требование
R1 в `AGENTS.md`).

```
knowledge/
  README.md            ← этот файл: формат и правила
  SKILL-SECTION.md     ← готовый блок для вставки в SKILL.md (шаг 0 и шаг 7)
  patterns/*.md        ← подтверждённые карточки паттернов
  REJECTED.md          ← отклонённые карточки: id, отпечаток, кто, почему
  patterns.py          ← НЕОБЯЗАТЕЛЬНЫЙ помощник (stdlib, без pip)
  hooks/stop-nudge.sh  ← НЕОБЯЗАТЕЛЬНОЕ напоминание в конце сессии
  measure/             ← измерительный стенд: инцидент №1 → инцидент №2
```

## Цикл

```
расследование №1 ──► агент ПРЕДЛАГАЕТ карточку ──► человек: да / правки / нет
                                                        │
                            patterns/<id>.md ◄──────────┤ да
                            REJECTED.md      ◄──────────┘ нет
                                     │
расследование №2 ──► шаг 0 читает карточки ──► совпало ──► гипотеза готова,
                                                            ищем улики, а не причину
```

Три свойства, ради которых всё это существует:

1. **В базу ничего не попадает без человека.**
2. **Отклонение — тоже знание** и оно навсегда: тот же паттерн не предложат снова.
3. **Молчание запрещено.** В каждом расследовании есть строка `ЗНАНИЯ: …` —
   что прочитано, что применено, что предложено или почему нет.

## Почему подтверждение происходит В СЕССИИ, а не по расписанию

В этом парке уже работают три «предлагающих» робота — drift-triage,
catalog-triage и ночной producer корректировок для tssa. Все три устроены
одинаково: таймер → агент → **draft PR** → человек смотрит и мержит. Принцип
взят оттуда, он проверен в проде: *«цикл, который правит собственную оснастку
без присмотра, незаметно роняет качество и накапливает ошибку каждую ночь»*.

Механизм оттуда взять **нельзя**: в корпоративном Qwen Coder CLI нет и не будет
планировщика, а любой демон нарушил бы R1.

И это оказалось не потерей, а выигрышем:

| | по расписанию (ночью) | в сессии (наш вариант) |
|---|---|---|
| когда человек подтверждает | через день-два, без контекста | сразу, инцидент ещё перед глазами |
| качество подтверждения | по памяти и по описанию | по фактам, которые он только что видел |
| что нужно эксплуатировать | таймер, очередь, PR-бот, доступы | ничего |
| работает при жёстком корп-локдауне | нет | да |

Асинхронная ночная проверка — это компромисс на случай, когда человека рядом
нет. Здесь он есть **всегда**: расследование по определению начинается с его
вопроса. Момент максимального контекста — это конец расследования, и именно
там мы спрашиваем.

Реализация — **обычный текст в SKILL.md** (шаг 7), без единого механизма.
Работает на любой версии CLI, при выключенных хуках, без прав на запуск команд.
Есть необязательное усиление — хук `Stop` внутри папки навыка
(`hooks/stop-nudge.sh`), который напоминает, если расследование закончилось, а
карточку не предложили. Хуки выключены или не поддерживаются — ничего не
ломается.

## Формат карточки

Markdown с YAML-frontmatter. **Держите её короткой — до ~85 строк**, то есть в
пределах одного экрана с прокруткой (нынешние три: 54, 74 и 84 строки).
Карточка, которую человек не станет читать перед подтверждением, бесполезна:
гейт превратится в проставление галочек.

```yaml
---
id: ssh-bruteforce-storm          # стабильный, kebab-case, = имя файла
title: Массовый перебор паролей SSH
kind: incident                    # incident | environment
severity: high                    # info | low | medium | high | critical
status: confirmed                 # proposed | confirmed | superseded
confirmed_by: operator            # КТО подтвердил. Заполняет человек, не агент
confirmed_at: 2026-07-28          # ISO-дата подтверждения
learned_from: "OpenSSH_2k.log, прогон eval/runs.jsonl #8"
signature_any:                    # КАК УЗНАТЬ: греппабельные выражения по строкам
  - "Failed password for"
  - "authentication failure;.*rhost="
signature_all: []                 # если нужно совпадение всех сразу
signature_filename: []            # подписи по ИМЕНАМ файлов (напр. "\.gz$")
confirm_threshold: "≥20 неудач и ≥3 источника за ≤1 ч; иначе это фон"
expected_saving: "поиск: ~4 шага → 1"
---
```

Обязательные разделы тела:

| раздел | зачем |
|---|---|
| `## Что это значит` | смысл паттерна человеческим языком |
| `## Корневая причина` | что чинить, а не что видно |
| `## Что делать` | конкретные действия |
| `## Обязательная проверка` | 1–2 поиска, отличающие находку от шума |
| `## Если совпало — что можно НЕ делать` | **обязателен**, см. ниже |
| `## Чем это НЕ является` | ложные срабатывания — самый полезный раздел |
| `## Улики` | `файл:строка` → цитата, **только проверенные** |
| `## Что карточка НЕ отменяет` | **обязателен**, см. ниже |
| `## История правок` | появляется, когда человек правил карточку |

### Почему раздел «что можно НЕ делать» обязателен

Первая версия формата его не имела, и **измерение это наказало**: карточка
только *добавляла* проверки, и warm-плечо оказалось на 25 % дороже по шагам
холодного при равном качестве. По трассам видно, куда ушла разница — не на
чтение базы (5–6 вызовов), а на лишние `run_shell_command` (43–46 против 16–35):
агент честно расследовал заново то, что уже знал.

Карточка, которая не говорит, что можно пропустить, — это не знание, а
дополнительный чек-лист. Поэтому раздел проверяется `patterns.py check`.

### Правила, которые проверяет `patterns.py check`

- `id` совпадает с именем файла; `id` уникален.
- Все обязательные поля непусты; `status` из допустимого множества.
- Есть хотя бы одна подпись, и все подписи компилируются как регулярки.
- **Есть раздел «Что карточка НЕ отменяет».**
- Подпись карточки не совпадает с отпечатком из `REJECTED.md`.

### Про экранирование

Разбор frontmatter намеренно примитивный (десяток строк, без библиотек) и
**не обрабатывает escape-последовательности**: пишите регулярку как есть, с
одним обратным слэшем — `"\.gz$"`, а не `"\\.gz$"`. Ограничение на входе стоит
дешевле, чем полноценный YAML-парсер в каждом агенте.

### Почему подпись, а не «описание ситуации»

Карточка обязана давать **конкретную строку для поиска**. «Сервис ведёт себя
странно под нагрузкой» — это не паттерн, это настроение. Проверка простая: если
по подписи нельзя выполнить поиск и получить строки — карточка не готова.

### Нижняя граница качества

Карточка экономит **поиск**, но никогда — **проверку**. Черновик, который
предлагает пропустить перечитывание цитат, не открывать часть корпуса или
поверить выводу без улик, — это не обучение, а деградация, и он не должен
предлагаться вовсе. Цикл удешевляет расследование **при неизменном качестве**.
Раздел «Что карточка НЕ отменяет» — механическое напоминание об этом, поэтому он
обязателен.

Отдельно: улики в карточке относятся к **прошлому** инциденту. Цитировать их в
новом отчёте нельзя — в новом корпусе нужны свои `файл:строка`.

## Человеческий гейт — что происходит на экране

Полный протокол (что печатает агент, что вводит инженер, как записывается
отказ) лежит в `SKILL-SECTION.md`, раздел «Шаг 7». Коротко:

- агент показывает черновик карточки в фиксированном формате;
- инженер отвечает одним из: `да` / `правки: …` / `нет: <причина>` / `позже`;
- `да` → файл в `patterns/`, `status: confirmed`, кто и когда;
- `правки:` → агент правит, **показывает снова** и спрашивает ещё раз; правка
  попадает в `## История правок` — это самый ценный сигнал во всём цикле:
  человек только что исправил модель мира агента;
- `нет:` → строка в `REJECTED.md`, в `patterns/` **ничего**;
- `позже` → не записывается ничего, и агент говорит об этом вслух.

Ответа нет (неинтерактивный прогон) — не записывается ничего. Записать карточку
может только человеческое «да» в этой же сессии либо руки инженера.

## Как отказ переживает переформулировку

В `REJECTED.md` кроме `id` лежит **отпечаток** — sha256 (12 знаков) от
нормализованного набора подписей. Агент, переформулировавший ту же самую идею
под другим именем, получит тот же отпечаток и получит отказ. Без скрипта
сравнение идёт по `id` и по тексту подписей — грубее, но работает.

## Как это попадает к коллегам

`git add knowledge/patterns/<id>.md && git commit`. Всё. Карточка — обычный
markdown: она диффается, ревьюится и откатывается штатными средствами. Никакого
обмена знаниями «через сервис» не предусмотрено намеренно.

## Помощник (необязательный)

    python3 patterns.py list                # что есть в базе
    python3 patterns.py match <каталог>     # какие карточки подходят к корпусу
    python3 patterns.py show <id>
    python3 patterns.py new <id>            # черновик в stdout, НЕ сохраняет
    python3 patterns.py reject <id> --reason "…" --by <кто> --signature "<re>"
    python3 patterns.py rejected
    python3 patterns.py check               # самопроверка базы

Только stdlib, python ≥3.9, `pip` не нужен. **Это удобство, а не зависимость.**
Измеренный факт: в неинтерактивном режиме (`qwen -p`) CLI по умолчанию
*отказывает* в запуске shell-команд, поэтому основной путь навыка написан под
чтение файлов и поиск по содержимому. Если скрипт не запускается — навык обязан
работать так же правильно, просто чуть медленнее.

## Измерения

Стенд и результаты — в `measure/`:

- `measure/METHOD.md` — методика: три ячейки, что одинаково в плечах, оговорки;
- `measure/run-kb.sh` — один прогон (`cold` = пустая база, `warm` = карточки на месте);
- `measure/batch-kb.sh` — весь эксперимент, плечи чередуются;
- `measure/merge-skill.py` — слияние `SKILL-SECTION.md` в SKILL.md по якорям;
- `measure/record.py` — запись в `measure/runs.jsonl`: шаги, время, токены **и
  детерминированный чек-лист качества** (быстрее не считается, если хуже);
- `measure/report.py` — сводная таблица; `measure/rescore.py` — пересчёт качества
  по сохранённым ответам;
- `measure/raw/` — полные транскрипты прогонов, чтобы любую цифру можно было
  перепроверить, а не поверить на слово;
- `measure/RESULTS.md` — что получилось на самом деле, включая то, что не подтвердилось.

Оба плеча получают **одинаковый текст навыка** и одинаковый запрос. Различается
только содержимое `patterns/`. Иначе мы измеряли бы «больше текста в промпте», а
не «переиспользование знания».
