# Primary-source research for Winevtx remediation

Checked 2026-09-07. Search terms contained only generic event IDs, product features and public forensic methodology; no private event content was sent to public search. The following engineering implications are our inferences, not claims that a standard mandates a particular Sherlock implementation.

| Source | Verified guidance | Implication and boundary |
|---|---|---|
| [Microsoft EventType schema](https://learn.microsoft.com/en-us/windows/win32/wes/eventschema-eventtype-complextype) | Event XML separates System from alternative EventData/UserData payloads and other payload forms. | Preserve raw fields and source pointers; do not assume one JSON payload shape. This XML schema does not specify our exporter's JSON representation. |
| [Microsoft 4625 documentation](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625) | Defines distinct Subject/Target fields, authentication package and LogonType; type 3 is network and type 10 remote interactive. | Type 3 alone cannot establish destination RDP, port or NLA state. Preserve source versus target account context and field-specific meaning. |
| [Microsoft Windows PowerShell 5.1 event logs](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_eventlogs?view=powershell-5.1) | Classic Windows PowerShell logs engine/provider lifecycle and can log command events. | Search both classic and operational evidence; absence of script-block IDs is narrower than absence of command evidence. Exact Winevtx HostApplication claims come from corpus, not this reference. |
| [Microsoft FW_RULE_ACTION specification](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fasp/702e3c23-c9d8-43db-8380-b4c670dd7f7d) | FW_RULE_ACTION_BLOCK=2 and FW_RULE_ACTION_ALLOW=3. | Decode within a verified provider/schema adapter; do not apply the enum globally to every field named Action. Event counts differ from distinct rule counts and effective final rules. |
| [NIST SP 800-86](https://nvlpubs.nist.gov/nistpubs/legacy/sp/nistspecialpublication800-86.pdf), sections 3.2–3.4 | Separates extraction, analysis and reporting; correlates multiple sources; documents steps and considers alternative explanations when evidence is incomplete. Published August 2006. | Separate raw observations/computations from interpretation. Preserve evidence and methods. This is methodological guidance, not a claim of legal certification. |
| [NIST SP 800-61r3](https://csrc.nist.gov/pubs/sp/800/61/r3/final), April 2025 | Current revision supersedes rev. 2 and integrates incident response with risk management. | Judge the report by whether supported conclusions and explicit gaps support response decisions; no deployment or incident-response policy change is proposed here. |
| [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), January 9, 2026 | Distinguishes task, trial, transcript and actual outcome; combines grading approaches and notes stochastic variation. | Evaluate the final report against sources plus execution evidence, not a tool exit or model self-assessment alone. Keep synthetic regression and end-to-end target assessment separate. Passing one target trial does not prove reliability. |
| [OpenAI harness engineering, locally preserved reference](/Users/a/Documents/projects/personal-os/docs/references/openai-harness-engineering.md) | Repository guidance favors explicit boundaries, reusable tools and mechanical enforcement of invariants. | Turn reproducible errors into tool-supported constraints; do not rely on longer reminders alone. Local text was supplied, so it was not searched as product documentation. |

## Deliberate gaps

Searches did not locate a sufficiently authoritative standalone Microsoft 5379 field-semantics page or a version-qualified LocalSessionManager 21/23/24/25 mapping in this pass. Microsoft Q&A, third-party event catalogs and community forum results were not promoted to authoritative specifications. For these Winevtx findings, preserve exact event payloads/rendered labels and the independent corpus calculations. Before shipping an offline semantics table, verify mappings against official provider metadata/message resources or a reproducible Windows export tied to OS/provider version. Unknown mappings remain unknown; do not ship a guessed decoder. PowerShell 7 documentation was discovered but is not substituted for the Windows PowerShell 5.1 authority above.
