# Отчёт по корпусу BlueSkyRansomware.jsonl — независимый разбор исходных событий

Проверено 2026-09-07. Это самостоятельно составленный проверяющим отчёт по оригинальным 469 записям. Целевая модель не завершила отчёт: её [неизменённый ответ](report-direct-original.md) содержит статус и неисполненные запросы инструментов. Этот документ не является успешным автономным результатом DeepSeek/Qwen и не повышает оценку запуска.

Источник: один файл, **467 262 байта, 469 JSONL-записей**, SHA256 `28b73f0be7b2a6ed7d102c8a8ba86d7c186887e0b71fcacfb8f73dcb0e37ff58`. Имя файла используется только как адрес источника; оно не доказывает наличие ransomware. Время ниже — UTC из SystemTime, номера строк физические. **[ФАКТ]** означает проверенные поля/агрегаты, **[ВЫВОД]** — интерпретацию с обозначенными пределами.

## 1. Основной результат

**[ФАКТ]** На `DESKTOP-7EQVM78` зарегистрированы **44 неуспешных и четыре успешных SQL Server-входа пользователя `sa` с клиентского IP `87.96.21.84`**. Все отказы содержат причину несовпадения пароля. Два коротких эпизода — 21 и 23 апреля 2024 года; после каждого потока из 22 отказов имеется успешный вход с теми же именем и адресом (`BlueSkyRansomware.jsonl:164`, строки 165–186; `BlueSkyRansomware.jsonl:432`, строки 433–455).

**[ВЫВОД]** Последовательность согласуется с автоматизированным подбором SQL-пароля, завершившимся доступом к `sa`. Успешная аутентификация непосредственно подтверждена, но происхождение пароля, его сложность и законность действий из событий не определяются. IP — наблюдаемый клиентский адрес, не идентификация человека или организации.

**[ФАКТ]** 23 апреля после успешных SQL-входов зарегистрировано изменение `show advanced options` и `xp_cmdshell` с `0` на `1` (`BlueSkyRansomware.jsonl:456`, `BlueSkyRansomware.jsonl:457`). Через 65.59 с после второй записи появляются события PowerShell с `HostName=MSFConsole`, `HostApplication=winlogon.exe`; двигатель переходит в `Available` (`BlueSkyRansomware.jsonl:459`, строки 460–467).

**[ВЫВОД]** Это подозрительная последовательность доступа к SQL и последующей активности PowerShell, требующая проверки возможной компрометации. Но в данных нет прямой связи SQL-сессии с изменением конфигурации, вызова xp_cmdshell с конкретной командой или дерева процессов, связывающего SQL Server и указанный PowerShell-хост. `winlogon.exe` — значение HostApplication без полного пути; оно не доказывает подлинность системного файла или внедрение в настоящий Winlogon. Название `MSFConsole` характерно для инструментария Metasploit, но одной строки недостаточно для безусловной атрибуции конкретному инструменту/оператору.

**[ФАКТ]** SecurityCenter сообщает `Windows Defender=SECURITY_PRODUCT_STATE_SNOOZED` начиная с **09:54:01Z 23 апреля** — раньше второго потока SQL-отказов в 09:59:54Z (`BlueSkyRansomware.jsonl:425`). Кто и как изменил состояние, не установлено. Прямых свидетельств шифрования файлов, ransomware-процесса, записки о выкупе или эксфильтрации в этих двух каналах не найдено; название семейства BlueSky из имени файла не выводится.

## 2. Состав и среда

Все 469 записей относятся к `DESKTOP-7EQVM78`; присутствуют только **Application — 336** и **Windows PowerShell — 133**. Удержанное окно: **2024-04-21T00:32:42.803382Z** (`BlueSkyRansomware.jsonl:1`) — **2024-04-23T10:11:10.425516Z** (`BlueSkyRansomware.jsonl:469`). Физический порядок отдельных соседних записей не всегда совпадает с SystemTime; хронология здесь строится по времени, а не только по номеру строки.

Основные провайдеры: MSSQLSERVER — 216, PowerShell — 133, Microsoft-Windows-Security-SPP — 42, SecurityCenter — 16, Windows Error Reporting — 11. Полный каталог — [source-summary.json](source-summary.json). У EventID поле `#text` — число; сравнение с текстом `'600'` дало бы неверный нулевой результат.

**[ФАКТ]** `BlueSkyRansomware.jsonl:71` и строка 238 содержат Microsoft SQL Server 2022 RTM **16.0.1000.6**, Developer Edition 64-bit, Windows 10 Pro build19045, Hypervisor. Строки 76/243 указывают VMware, Inc. / VMware20,1. Эти поля описывают среду, но сами по себе не объясняют инцидент.

**[ФАКТ]** MSSQLSERVER 26022 фиксирует слушатели `'any'` IPv6/IPv4 на **1433** (`BlueSkyRansomware.jsonl:121`, `BlueSkyRansomware.jsonl:122`; повторно строки 277–278). На 1434 указаны loopback `::1` и `127.0.0.1` (строки 125–126,281–282). Также указаны named pipes (строки 123–124,279–280). Это поддерживает наличие SQL-слушателя 1433, но успешные входы 18454 не содержат собственного destinationport: точный сетевой маршрут каждого входа этим не доказан.

Ранние команды описывают разные действия: проверки INF-файлов (`BlueSkyRansomware.jsonl:9`); команду остановки процессов с путём VSCode `code-tunnel.exe` (строки 24–31); Start/Stop/Start службы npcap (строки 32–39); Register-ScheduledTask `npcapwatchdog` с CheckStatus.bat, SYSTEM и AtStartup (строки 40–47). **[ФАКТ]** Строки запуска содержат эти команды. **[ОГРАНИЧЕНИЕ]** Они не удостоверяют конечный результат каждой операции или злой умысел: npcap/VSCode-контекст согласуется также с администрированием и установкой программ.

## 5. Defender, фоновые события и пределы отрицаний

Из 12 SecurityCenter 15 восемь имеют состояниеON, четыре — SNOOZED. ПоследнееON перед сменой — **23 апреля 09:52:59.188634Z** (`BlueSkyRansomware.jsonl:423`); первоеSNOOZED — **09:54:01.302195Z** (строка 425), затем 427–429. После этого имеются SecurityCenter 2/1 (строки 430–431), но нет новой записи 15, подтверждающей восстановление ON. Названия состояний сохранены буквально: нельзя без дополнительных данных приравниватьSNOOZED к конкретной команде полного отключения всех функций Defender.

Сам канал Microsoft-Windows-Windows-Defender/Operational отсутствует. Поэтому здесь нет достаточного покрытия для вывода «Defender ничего не обнаруживал». Смена состояния раньше второго SQL-потока не позволяет приписать её входу 09:59:54 или появившемуся позже MSFConsole.

`BlueSkyRansomware.jsonl:55` имеет EventID4625 провайдера **Microsoft-Windows-EventSystem** и поля SuppressDuplicateDuration; это не неуспешный Windows-вход Security. VSS8224 (включая строку 424) без команды удаления теневых копий не доказывает саботаж резервных копий. WER1001 (включая строку 468 с SearchApp.exe/RADAR_PRE_LEAK_64), перезапуски и фоновые SQL-события не отнесены к атаке без отдельной причинной связи.

В корпусе нет каналов Security, System, Sysmon, RDP/TerminalServices, DefenderOperational или PowerShellOperational. В этих 469 записях нет 4103/4104, но EID800 и HostApplication дают часть командной информации. Не найдено событий, прямо показывающих шифрование/переименование файлов, записку о выкупе, вредоносный исполняемый файл, C2-соединения или вынос данных. Это предел данного набора, не доказательство отсутствия таких действий на машине.

## 6. Практический вывод

Обоснованный предмет расследования — **успешный доступ к SQL Server под sa после серии неверных паролей**, изменение конфигурации xp_cmdshell и последующий необычный PowerShell-хост. Заявлять только «неуспешный перебор» было бы неверно: четыре успешных входа есть. Заявлять доказанную атаку BlueSky ransomware, конкретный эксплойт или завершённую цепочку SQL→xp_cmdshell→инъекция в Winlogon→шифрование было бы сильнее имеющихся свидетельств.

Для завершения причинного разбора нужны SQLERRORLOG/аудит с сессиями и командами, история конфигурации и runtimeзначений, процессные/сетевые события вокруг 10:00–10:02, сведения о законности использования 87.96.21.84 и причинах состояния Defender. При отсутствии санкционированного объяснения успешный доступsa следует рассматривать как возможную компрометацию и проверять доступностьSQL, учётные данные и исполнение на хосте. Какие действия уже выполнены операторами, этот отчёт не утверждает.

Семантика SQL18453/18454/18456 сверена с [каталогом Microsoft Database Engine18000–18999](https://learn.microsoft.com/en-us/sql/relational-databases/errors-events/database-engine-events-and-errors-18000-to-18999?view=sql-server-ver16). Связь названияmsfconsole с Metasploit описана в [документации Rapid7](https://github.com/rapid7/metasploit-framework/blob/master/docs/metasploit-framework.wiki/Using-Metasploit.md); она поддерживает только осторожную интерпретацию имени хоста, а не идентификацию бинарного файла в этом инциденте.
