# Кейс: умная регрессия по диффу MR (testing)

Тренировочный кейс для трека «testing»: по диффу merge request'а агент
выбирает минимально достаточный набор регрессионных тест-кейсов и заводит
прогон в TMS.

Что внутри:

- `app/` — мини-бэкенд интернет-магазина (каталог, корзина, оформление,
  авторизация, уведомления) + его собственные юнит-тесты в `app/tests/`
  (иллюстрация «кода проекта»; регрессионная карта живёт отдельно, в TMS);
- `diff.patch` — дифф MR !1: изменены `app/cart.py` (валидация количества:
  лимит позиции 99 → 20 + проверка остатков) и `app/checkout.py` (модель
  скидок: суммирование → best-of, новый промокод, порог лояльности);
- `testcase-map.json` — карта из 25 регрессионных кейсов с покрытием по
  файлам (`files_covered`), приоритетами и длительностью;
- `expected-selection.json` — эталонная выборка (смотреть ДО прогона агента
  нельзя: это ответы);
- `benchmark.py` — метрика выборки.

Моки зеркалируют кейс: forge-мок отдаёт MR !1 с этим самым диффом и исходники
`app/`, TMS-мок отдаёт эти самые 25 кейсов (тесты моков стерегут совпадение).

## Как прогнать кейс

1. **Поднять моки** (из корня репозитория):

   ```bash
   python3 mocks/run_all.py   # forge на 127.0.0.1:8803, tms на 127.0.0.1:8804
   ```

2. **Запустить агента** со скиллом `tracks/testing/skill.md`. Агент обязан:
   снять дифф через forge MCP (`mcp/forge_mcp.py`: `get_mr`, `get_mr_diff`),
   снять карту кейсов через tms MCP (`mcp/tms_mcp.py`: `list_testcases`),
   разметить прямое и транзитивное покрытие, собрать `selection.json`
   (обоснование по каждому кейсу) и завести прогон (`create_run`).

3. **Посчитать метрику**:

   ```bash
   python3 cases/testing-regression/benchmark.py selection.json
   ```

   Бенчмарк печатает таблицу «выбрано vs эталон», recall по `must_run`
   (цель — 1.00), efficiency (доля отсечённых кейсов) и оценку сэкономленного
   времени; пропущенные P1-кейсы кричат отдельным блоком. Код выхода 1 при
   любом пропуске `must_run` — удобно ставить в CI. ⚠️ Вывод раскрывает
   эталонную выборку — ручной бейслайн тест-лида снимайте ДО первого запуска
   бенчмарка. Самопроверка бенчмарка:

   ```bash
   python3 cases/testing-regression/benchmark.py --self-test   # recall = 1.0
   ```

## Метрика хакатона

Демо-история строится на двух числах:

1. **Сэкономленное время регрессии** — полный прогон карты ~189 минут;
   эталонная выборка — ~114 минут работы вместо всей регрессии
   (efficiency 0.48 при recall 1.00). Сравнивайте с ручным бейзлайном:
   сколько кейсов выбрал бы тест-лид руками и за сколько минут.
2. **% пропущенных дефектов** — доля пропущенных `must_run`-кейсов
   (1 − recall); пропущенный P1 — это «улетевший в прод дефект», бенчмарк
   подсвечивает такие случаи громче всего.
