# Sherlock — анализ логов и поиск причин инцидентов

Навык для **Qwen Coder CLI**, который по логам находит корневую причину и
предлагает решение. Работает с логами **любого формата, любого размера, на любом
языке** — включая форматы, которые никто заранее не описывал.

## Установка — один шаг

Скопируй папку навыка туда, где Qwen Coder ищет навыки:

```bash
cp -r cases/06-dev-logging/sherlock/skills/v11 ~/.qwen/skills/log-rca
```

Всё. Больше ничего настраивать не нужно: ни переменных окружения, ни ключей, ни
конфигов, ни MCP-серверов, ни установки пакетов.

**Каталог должен называться `log-rca`.** Имя самого навыка — `sherlock` (поле
`name:` в `SKILL.md`), а `log-rca` — это каталог, на который записаны пути к
инструментам внутри навыка. Под другим именем каталога инструменты молча не
запустятся. Подробно — `cases/06-dev-logging/README.md`, раздел «Два имени».

Проверить:

```
qwen
> у меня упал сервис, логи в /путь/к/логам — разберись что случилось
```

## Как пользоваться

Навык срабатывает сам, когда речь заходит о логах или об инциденте. Примеры:

- «Заказ упал в FAILED, логи в `logs/` — найди причину и место в коде.»
- «Вот дамп за ночь (`logs.tar.gz`) — почему деградировал прод?»
- «Тут journald с хоста, кто-то ломится по SSH? Что делать?»
- «Разбери инцидент по correlation_id `c-8f3a2b91`, код в `./repo`.»

Он сам составит карту корпуса, сузит поиск, прочитает нужные строки, проверит
гипотезы и выдаст отчёт с цитатами `файл:строка`.

## Почему это работает без парсеров

Модель читает Envoy access log, BSD syslog без года, logcat, zap JSON, Java
stacktrace и самописный формат чьей-то команды одинаково хорошо. Писать под
каждый формат парсер — бесконечная работа, которая всё равно ломается на
следующем незнакомом формате.

Измерено на корпусе 649 МБ / 4,26 млн строк / 31 файл / 26 форматов, с 11
заранее заложенными дефектами и 2 приманками. Один судья (`gpt-5.5`), одна
модель (`[SP]deepseek-v4-flash`), один и тот же корпус:

| | без навыка | с навыком (4 прогона) |
|---|---|---|
| найдено дефектов | **0 из 11** | **7–9 из 11** |
| приманок выдано за причину | 1 из 2 | 1–2 из 2 |
| входных токенов | 2 196 102 | 7,0–18,8 млн |

Без навыка модель **не молчит**: она пишет уверенный отчёт на 12 435 символов
со ссылками на 12 файлов и не находит ни одного из одиннадцати дефектов. Разбор
идёт без единой строки парсера — включая самописный pipe-формат с выдуманным
словарём уровней (`ALARM`/`FATALITY` выше `WARN`) и лог на русском языке.

Честно о границах, всё измерено:

- разброс судьи **±1 дефект** на одном и том же тексте — одно число называть нельзя;
- **приманки навык не отсеивает лучше базовой линии** — это открытый дефект;
- цена — примерно **3–5× токенов и 9× времени**;
- ограничение — не формат, а **покрытие**: на одном корпусе и одной модели
  результат менялся только из-за того, какие файлы агент открыл. Поэтому в
  навыке есть отдельная дисциплина покрытия.

Каждая цифра прослеживается до строки реестра
`cases/06-dev-logging/sherlock/eval/bench/scores-bench.jsonl`, посчитанной
`score-bench.py` по ответному ключу — ни одна не снята глазами.

## Что внутри

```
cases/06-dev-logging/
├── 06-dev-logging.md         постановка задачи от организаторов
├── petstore_input_pack.zip   их же входные данные
├── docs/specs/               дизайн решения и доказательная база
└── sherlock/
    ├── skills/               навык (v11 — поставка; v1–v10 заморожены как армы A/B; README внутри)
    ├── tools/                прежняя линия инструментов v8–v10; v11 держит свою копию в skills/v11/tools/
    ├── verify.sh             проверка, что навык работает в реальном Qwen Coder
    ├── measure/              измерительный стенд: слайсы, реестр, сверка прогонов
    └── eval/                 замеры: baseline vs версии навыка, корпус 649 МБ
```

## Замеры

`eval/run.sh <каталог-логов> <арм>` (арм = каталог в `sherlock/skills/`: `none`,
`v1`…`v12`) — один замер, дописывается в
`eval/runs.jsonl` (arm, turns, время, токены, покрытие файлов, ссылки на строки).
`arm=none` — та же модель без навыка, это baseline.

`eval/batch.sh none v1` — матрица по датасетам.
