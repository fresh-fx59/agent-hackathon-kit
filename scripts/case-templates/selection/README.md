# Кейс «__CASE_SLUG__» (режим selection: умный выбор регрессионных тестов)

Каркас кейса, где агент по диффу/MR и карте тест-кейсов выбирает, **какие
тесты гонять**, и пишет `selection.json`; бенчмарк считает **recall** по
обязательному набору (`must_run`, цель 1.0) и **efficiency** (насколько
меньше тестов, чем полный прогон). Образец боевого кейса:
`cases/testing-regression`.

## Файлы кейса

| Файл | Что это |
|------|---------|
| *(добавьте дифф)* | Например `diff.patch` — изменения, от которых считается риск. |
| `testcase-map.json` | Карта тест-кейсов: id, область, приоритет, покрываемые файлы, длительность, последний результат. |
| `expected-selection.json` | Эталон: `must_run` (обязательные), `nice_to_run` (желательные), `rationale`. |
| `benchmark.py` | Скоринг: recall / efficiency, таблица по кейсам, экономия времени; exit 1 при пропуске must_run. |

## Вход

ЗАПОЛНИТЕ: положите дифф (например, `cases/__CASE_SLUG__/diff.patch`) и
реальную карту тест-кейсов; опишите здесь, что меняет MR.

## Как прогнать агента

ЗАПОЛНИТЕ под ваш кейс; типовой ход (см. `cases/testing-regression/README.md`):

1. При необходимости поднимите моки (TMS): `python3 mocks/run_all.py`.
2. Запустите агента с навыком трека (`tracks/testing/skill.md`), подав дифф и
   `testcase-map.json`; агент пишет `selection.json` вида
   `{"selected": [{"id": "TC-3", "reason": "..."}], "strategy": "..."}`.

## Бенчмарк

```bash
python3 cases/__CASE_SLUG__/benchmark.py selection.json               # полный отчёт
python3 cases/__CASE_SLUG__/benchmark.py selection.json --score-only  # recall для CI
python3 cases/__CASE_SLUG__/benchmark.py --self-test  # must_run против себя, recall = 1.0
```

Пропущенный must_run — прокси пропущенного дефекта (P1 подсвечивается
отдельно); exit-код 1 при любом пропуске, так что бенчмарк можно ставить
гейтом в CI.

## Ручной бейслайн (для демо «агент vs человек»)

1. Один участник **до** запуска агента читает дифф и карту тестов и руками
   составляет свой `selection-manual.json`, с таймером.
   ⚠️ Спойлер: бенчмарк печатает эталонный must_run — «ручной» участник не
   должен запускать `benchmark.py` и открывать `expected-selection.json`,
   пока не закончит, иначе бейслайн испорчен подсказками.
2. Запишите: время, recall и efficiency человека — и то же для агента.
3. Табличка «человек: N минут / recall X, агент: M минут / recall Y» — в демо.
